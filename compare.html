Cross-reference patterns

HubSpot
Inline links to dependency concepts. Cross-connector redirects in paragraph 2 of every connector landing. FAQs bundled into the parent setup page as a final H2. No "Related articles" footer.
Egnyte
Inline links to dependency articles in the intro paragraph. "Additional Resources" footer = plain bulleted link list, hand-curated. No callouts wrapping cross-refs.
DocSend
Inline links throughout. "Related Articles" footer = 4 cards (heading + snippet) of sibling articles in the same H2 group on the product index. Lateral discovery, not next-step.
Vera
IA-driven. Section index pages are the table of contents. "New in Vera X.Y" inline annotations point to release notes for version-specific behavior. Minimal lateral linking.

Page-scope (split) rules

Platform Inferred rule Example
HubSpot One user-visible verb per page Install / Customize / Track / Log / Use sales tools / Manage meetings / Troubleshoot / Uninstall — all separate
Egnyte Audience-based + concept-based split Outlook add-in has a User Guide and a Configuration Guide as separate pages
DocSend One feature + one outcome = one page Watermarks, allow/block, passcode, email auth, email validation — all separate, despite sharing the link-settings panel
Vera One UI menu entry per page (very granular) Approve records and Reject records are sibling pages, not sections of one page
