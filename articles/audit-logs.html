Review audit logs & usage dashboards

SpecterX records every file access, share, download, and login event in the Audit Logs, and surfaces sharing volume and domain breakdowns in the Domains Dashboard. Together, these two views give administrators the visibility needed to enforce compliance, investigate incidents, and understand how your organization uses SpecterX.

Before you get started

  • Permissions required. Administrators or users with the Auditors role. Users with the Auditors role can view audit logs and dashboards but cannot modify policies or user settings.
  • Data retention. Audit log retention depends on your organization's subscription tier. Contact your SpecterX administrator or account manager for your organization's retention period.
  • Export format. Audit log exports are delivered as a CSV file. The CSV includes all columns visible in the on-screen table plus additional metadata columns (event timestamp, file ID, IP address) not shown in the default view.
  • Limitations. The audit log shows events for files managed by your SpecterX tenant only. Events from recipients accessing a file on their own device via a third-party viewer (such as Adobe Reader) after a download are not captured unless Rights Management (RMS) is enabled.

Open the Audit Logs page

1

In the left navigation, click Audit logs.

The Audit Logs page opens at /audits. The log is sorted by most recent event first and is paginated at 25 rows per page.

Read the audit log table

The audit log table shows the following columns by default:

ColumnWhat it shows
OperationThe event type displayed as a badge: Share, Open, Download, Delete, Login, Policy change, Permission change.
File NameThe name of the file involved in the event. Empty for Login events.
Affected usersThe user who performed the action (sender) or was affected by the action (recipient).

Additional columns available in the exported CSV (not shown on screen by default):

  • Timestamp — exact date and time of the event in UTC.
  • File ID — the internal SpecterX identifier for the file. Useful for correlating events across multiple rows.
  • IP address — the IP address from which the event was initiated.
  • Policy — the security policy active on the file at the time of the event.

Filter audit log entries

1

To narrow the log to events by a specific user, type their email address in the User field at the top of the page and press Enter or click Apply.

2

To filter by event type, click the All Operations dropdown and select one of the available operation types: Share, Open, Download, Delete, Login, Policy change, or Permission change.

3

To find events for a specific file, enter its exact file name in the File Name field, or enter its File ID in the File ID field. File IDs are found in the file detail view or in previously exported CSVs.

4

Click Apply to run the filters. The log table refreshes to show only matching entries.

To clear all filters and return to the full log, click clear filters.

Tip: Combine the User filter with the Download operation type to quickly identify which recipients have downloaded copies of a particular file.

Export the audit log to CSV

1

Apply any filters you want (for example, a specific date range or file name) to limit the export to the events you need.

2

Click Export CSV at the top-right of the log table.

The browser downloads a CSV file named audit-log-<date>.csv. Open it in Excel, Google Sheets, or any spreadsheet tool for further analysis.

Note: The CSV export applies the currently active filters. If you want to export the complete log without filtering, clear all filters before clicking Export CSV.

Review the Domains Dashboard

The Domains Dashboard provides a high-level view of sharing activity across your organization, broken down by the external domain of the recipients. It answers questions like: Which external domains receive the most shares? and How many files are we sharing with each domain?

1

In the left navigation, click Domains dashboard.

The dashboard opens at /domains-dashboard and shows the total number of shares across your organization.

2

Review the two donut charts:

  • Shares per domain — shows what percentage of your total shares went to each recipient domain. Hover over a segment to see the exact count.
  • Files sharing per domain — shows what percentage of unique files were shared with each domain. A domain may receive many shares of a single file (high on the left chart, low on the right) or many unique files (higher on the right chart).
3

Scroll down to the per-domain table for exact numbers:

  • Number of shares sent — total share events to that domain.
  • Number of files shared — total unique files shared with that domain.

Use this table to identify domains that receive a disproportionately large volume of shares — a potential indicator of policy misconfiguration or data exfiltration risk.

Interpreting the data

SignalPossible interpretationRecommended action
A new external domain appears with a high share count A new project, partner, or — rarely — an accidental mass-share to an unintended domain Cross-reference with the Audit Log filtered by that domain to identify the files and users involved
Internal domain (yourcompany.com) has a high share count Normal — staff sharing files with colleagues No action required; expected pattern
Unknown personal email domain (gmail.com, yahoo.com) in the top 5 Files being shared to personal email — possible policy exception or intent to exfiltrate Review the Audit Log for those shares and confirm the sender had authorization. Consider adding a policy restriction on sharing to personal domains.
